# Decision Score V1 — knowledge extraction

The accepted Core V1 `decision-score-v1` is a 0–10 analytical-strength compression, not a coverage fraction, confidence, probability, expected return, BUY/SELL signal, allocation, order, or gate clearance. Primary authority at legacy commit `f88b44d514fc9a2654040aa04e5350fc9e8660fe`: `docs/DECISION_SCORE.md`, `app/scoring/engine.py#COMPONENTS,build_scorecard`, and `tests/unit/test_decision_score.py`. The portfolio canonical score material governs immutable scorecard lineage for portfolio consumers; it does not replace the score formula. Lite stores only a review-required contract, no evaluator.

Ten component weights are fixed and sum to `1.00`: earnings acceleration `.15`; market regime, sector rotation, smart money evidence, relative strength, price structure, volume/OBV/VWAP, Ichimoku/MTF, and valuation/risk-reward `.10` each; liquidity/SMC traps `.05`. `decision_score_v1.json` pins every mandatory and optional Dxx input from the legacy `COMPONENTS` tuple. An admitted explicit diagnostic state contributes its mapped 0–10 state score; each eligible component averages admitted mandatory and available optional scores, then multiplies by its fixed weight. Data confidence is recorded separately, never multiplied into score. Analytical warnings remain separate.

Missing, unverified, cross-registry, future-as-of or inadmissible mandatory input makes its component `INELIGIBLE`, with null component score and contribution. If any component is ineligible, score status is `SCORE_INCOMPLETE` and final score is null. Missing optional input makes that component `PARTIAL` but may leave final score `COMPLETE` when all mandatory inputs qualify. The final sum never renormalizes weights. The legacy state lookup contains an `INSUFFICIENT_DATA: 0` entry, but score-input admission rejects unavailable/ineligible diagnostics before contribution: missing evidence is not silently zero.

D35 and D57 are optional dependencies of `volume_obv_vwap` and `liquidity_smc_traps` respectively. Both remain quarantined in Lite. They are unavailable, with no proxy or replacement; those components remain partial if their mandatory D11 and D08 inputs are admitted. Quarantine alone does not force `SCORE_INCOMPLETE`, because neither is mandatory. Their named source semantics must be separately resolved before future eligibility. This is captured in `SCORE_DEPENDENCY_MAP.json`.

Architecture: normalized evidence → 61 diagnostics → 10-point score, alongside six independent gates → strategy evaluation → final governed synthesis. Score completeness and gate readiness are separate. A high score cannot rescue a failed critical gate; a gate PASS does not imply a good stock. No score authorizes BUY/SELL, execution, broker orders, or overriding a gate. Future score computation requires separately reviewed runtime/source contracts.
